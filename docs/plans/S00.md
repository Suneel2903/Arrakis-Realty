# S00 plan: repo scaffold

Brief: docs/sessions/S00-scaffold.md. One PR.

## 1. Workspace root
- `package.json` (private, `packageManager: pnpm@10`), `pnpm-workspace.yaml` listing `apps/*`, `packages/*`.
- Root scripts: `lint`, `typecheck`, `test`, `db:migrate` fanning out with `pnpm -r`.
- `.nvmrc` (22), `.editorconfig`, `.gitattributes` (`* text=auto eol=lf`, so Windows checkouts stop flipping files to CRLF; `*.docx`/`*.pptx` binary).

## 2. apps/web (Next.js)
- Next.js 15 App Router, TypeScript `strict: true`, Tailwind v4, shadcn/ui initialised (`components.json`, `lib/utils.ts`, one `Button` to prove it works).
- `output: "standalone"` for a small Cloud Run image.
- Pages: `/` placeholder and `/api/health` that returns `{ ok, db }` (runs `select 1` on the DB). This health route is what "serves the web app" means in the done check.
- ESLint (next config), Vitest with one test for the health handler.
- `Dockerfile` (multi-stage, node:22-alpine, non-root, standalone output).

## 3. services/rera-pipeline (Python 3.12)
- `uv` project: `pyproject.toml` with `requires-python = ">=3.12,<3.13"`, `uv.lock`, package `rera_pipeline` under `src/`.
- ruff (lint + format), pytest, mypy is out of scope (not in brief).
- CLI stub `python -m rera_pipeline --help` with sub-commands `fetch | parse | locate | enrich | export` that exit "not implemented yet". S01 fills them in.
- One smoke test. `Dockerfile` (python:3.12-slim + uv, non-root).

## 4. packages/db (migrations)
- `migrations/0001_init.sql` = docs/DATA-MODEL.sql copied verbatim. Applied exactly as written (I won't change it in this PR).
- Runner: a small TypeScript script (`postgres` npm client) that keeps a `schema_migrations(version, applied_at, checksum)` table, applies pending `NNNN_*.sql` files in order inside one transaction each, and refuses to run if an applied file's checksum changed.
- Test: runs the migrations against a real PostGIS DB (CI service container / compose), then checks that all 7 tables plus `schema_migrations` exist.

## 5. docker-compose.yml
- `db`: `postgis/postgis:16-3.4`, healthcheck, named volume.
- `migrate`: one-shot, runs the packages/db runner, depends on healthy `db`.
- `web`: built from apps/web Dockerfile, port 3000, depends on `migrate` completing.
- `pipeline`: built from services/rera-pipeline, under profile `pipeline` so `docker compose up` doesn't run it by default.
- Uses `.env` if present; compose provides a local-only `DATABASE_URL` default for the local DB (not a secret).

## 6. GitHub Actions
- `ci.yml` (PRs + main): jobs `web` (pnpm install, lint, typecheck, test), `db` (PostGIS service, migrate, test), `pipeline` (uv sync, ruff check, ruff format --check, pytest), and `images` (docker build both images, no push).
- `deploy-staging.yml` (push to main, after CI): auth with `google-github-actions/auth` using workload identity federation (no JSON keys), build and push to Artifact Registry `asia-south1`, `gcloud run deploy` web and `gcloud run jobs deploy` rera-pipeline in `arrakis-staging`.
  - Needs repo variables: `GCP_PROJECT_ID`, `GCP_WIF_PROVIDER`, `GCP_DEPLOY_SA`, `GCP_AR_REPO`. **The GCP side (WIF pool, service account, Artifact Registry repo, Cloud SQL) isn't set up yet and I can't create it from this session.** The deploy job checks for these variables and skips with a notice while they're missing, so CI stays green. I'll write the `gcloud` setup steps in `docs/DEPLOY.md`.

## 7. .env.example
- Already lists every variable with no values. I'll add any new ones the scaffold introduces (e.g. `POSTGRES_*` for compose) with no values.

## Out of scope
Auth, payments, any real pages, pipeline logic, Cloud SQL provisioning.
